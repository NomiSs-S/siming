# Notes techniques : ExtendScript et CEP

Pièges rencontrés ou anticipés. Ajouter chaque découverte ici, avec la version
d'After Effects où elle a été observée. Les notes propres à ScriptUI (abandonné) ont été retirées avec l'ancienne version.

## Langage ExtendScript (cœur hôte)

- Moteur **ES3**. Absents : `Array.prototype.forEach / map / filter / indexOf`, `String.prototype.trim`, `JSON`, `Object.keys`, `let`, `const`, fonctions fléchées, `Function.prototype.bind`. Écrire des boucles `for` classiques.
- `new Function('log', code)` (ES3) compile un corps de fonction : c'est ainsi que Claude Code exécute du code avec `return` et `log()` (`host/tools/mcp.jsx`). Une erreur de syntaxe est levée à la construction. À vérifier dans AE : `e.line` d'une erreur dans ce code compte-t-il depuis la première ligne du code envoyé ?
- `try / catch / finally` est supporté. Mettre `app.endUndoGroup()` dans le `finally`.
- Les objets d'erreur ont `message`, `line` et `fileName`.
- Fichiers source lus dans l'encodage système sauf si un **BOM UTF-8** est présent : sans BOM, les accents s'affichent mal sur Windows.
- `$.fileName` donne le chemin du script en cours : le lire **au chargement** et le stocker.
- `$.evalFile(fichier)` évalue un fichier et renvoie la valeur de sa dernière expression.
- `Folder.getFiles("*.jsx")` renvoie des `File` et des `Folder` : tester `instanceof File`.
- `encodeURIComponent` / `decodeURIComponent` existent : utilisés par le pont pour transporter les arguments sans risque d'injection.

## Modèle objet After Effects

- `comp.layer(i)` et `layer.parent` renvoient un **nouvel objet à chaque accès** : `comp.layer(1) === comp.layer(1)` est faux. Comparer `index` ou `id`.
- Index de calques à partir de **1** ; `comp.numLayers` donne le nombre. Idem `app.project.item(i)` / `app.project.numItems`.
- `Layer.id` existe depuis AE 22.0 ; avant, repli sur `index`, qui change quand on réordonne.
- `app.project.activeItem` peut être une comp, un métrage, un dossier ou `null` : tester `instanceof CompItem`.
- `layer.parent = autreCalque` ou `= null` **compense les transformations** comme le menu Parent : position apparente conservée. `layer.setParentWithJump()` garde les valeurs brutes (le calque saute).
- La compensation se fait à l'instant courant : avec des keyframes ou des expressions, d'autres images peuvent sauter (comportement natif).
- Un calque verrouillé lève une erreur si on modifie `parent` ou `comment` : tester `layer.locked`.
- Parenter un calque à l'un de ses descendants lève une erreur (cycle) : envelopper dans un `try`.
- `layer.comment` : chaîne libre visible dans la timeline, bon support d'une mémoire persistante discrète.
- `comp.selectedLayers` : tableau d'objets calque, dans l'ordre de sélection.
- `layer.label` : index d'étiquette, 0 (aucune) à 16. Les couleurs sont dans les préférences : `app.preferences.getPrefAsString('Label Preference Color Section 5', 'Label Color ID 2 # n')` renvoie **4 octets ARGB sous forme de caractères**, pas un texte hexadécimal (`getPrefAsLong` échoue). Les lire avec `$.appEncoding = 'BINARY'` (un caractère par octet), puis rendre l'encodage ; repli sur les couleurs par défaut si la forme est inconnue. Dans le fichier de préférences, les octets imprimables apparaissent entre guillemets (`FFB5"88"` = B53838).
- **Lissage temporel** : `setTemporalEaseAtKey(k, inEase, outEase)` veut des tableaux de `KeyframeEase` dont la longueur dépend de la propriété : 1 pour une propriété spatiale ou 1D, 2 ou 3 pour une propriété 2D/3D non spatiale (échelle). Lire `keyInTemporalEase(k).length` pour connaître la bonne longueur. Passer d'abord `setInterpolationTypeAtKey(k, BEZIER, …)` : changer l'interpolation remet l'ease par défaut. `KeyframeEase` refuse une influence hors 0,1–100.
- **Sens des lissages** (2026-10-06) : After Effects nomme ses keyframes de leur point de vue (Easy Ease In = côté **entrant**, `keyInTemporalEase`). L'animateur parle du mouvement : « entrée » = son départ = côté **sortant** de la première keyframe. Quick Tools suit l'animateur (mode `in` → `keyOut…`) : ne pas « corriger » en relisant le code.
- **Décaler des keyframes sans en créer** (2026-10-06) : `setValueAtTime(t, v)` crée une keyframe à `t` s'il n'y en a pas, et laisse les autres : pour déplacer toute une animation, parcourir `numKeys` et `setValueAtKey(k, keyValue(k) + delta)`. Sur une propriété spatiale (`isSpatial`), relire `keyInSpatialTangent(k)` / `keyOutSpatialTangent(k)` avant et les reposer avec `setSpatialTangentsAtKey` quand `keySpatialAutoBezier(k)` est faux : les tangentes automatiques se recalculent seules, et en reposer une à la main la rend manuelle. À vérifier dans AE : `setValueAtKey` conserve-t-il les tangentes manuelles sans cette précaution ?
- **`setValue` sur une propriété animée** échoue : tester `numKeys > 0` et utiliser `setValueAtTime(temps, valeur)` (keyframe posée à l'instant courant).
- **Dimensions séparées** (`position.dimensionsSeparated`) : `ADBE Position` ne se pose plus, il faut écrire `ADBE Position_0` et `ADBE Position_1`, qui n'existent dans `property()` qu'en mode séparé.
- **Pseudo-effet à plusieurs curseurs** (ex. « Elastic Controller ») : impossible à créer par script, mais un préréglage `.ffx` qui le contient s'applique partout avec `layer.applyPreset(File)`, la définition étant embarquée dans le fichier. `applyPreset` vise les calques **sélectionnés** : isoler la sélection sur le calque voulu, puis la rétablir (`layer.selected`).
- **Masques et boîte d'un calque** (2026-10-07) : `sourceRectAtTime` **ignore les masques**. Pour la partie visible, lire `layer.property('ADBE Mask Parade')` : chaque masque a `maskMode` (`MaskMode.NONE`, `ADD`, `SUBTRACT`, `INTERSECT`, `LIGHTEN`, `DARKEN`, `DIFFERENCE`), `inverted`, `property('ADBE Mask Shape').valueAtTime(t, false)` (objet `Shape` : `vertices`, `inTangents`, `outTangents` relatives aux sommets, `closed`, en espace du calque) et `property('ADBE Mask Offset')` (étendue, en pixels). La boîte d'un tracé doit compter les extrema des courbes, pas seulement les sommets (`SIMING.geom.pathBounds`). Voir `SIMING.ae.visibleRect`. La matte de piste n'est pas lisible ainsi.
- **`sourceRectAtTime(t, false)`** donne la boîte visible dans l'espace du calque (`top`, `left`, `width`, `height`) ; absente sur les caméras et lumières (`typeof layer.sourceRectAtTime !== 'function'`). Pas de `toComp` en ExtendScript : composer soi-même ancrage, échelle, rotation, position et la chaîne des parents (matrices 2D dans `quicktools.jsx`).
- Le `Layer` est un `PropertyGroup` : `numProperties` et `property(i)` permettent de parcourir toutes ses propriétés (utile pour chercher une expression).
- **Mots réservés d'ES3** (2026-10-07) : `short`, `int`, `long`, `char`, `byte`, `float`, `double`, `boolean`, `final`, `native`, `goto`… sont réservés pour l'avenir en ES3 ; ExtendScript peut refuser tout le fichier. Ne pas les prendre comme noms de variable (Node, lui, les accepte : les tests ne le voient pas).
- **Déplacer des keyframes dans le temps** (2026-10-07, Boîte à outils) : aucune API ne le fait. Lire chaque keyframe (valeur, interpolations, ease, continuité et Bézier auto temporels, tangentes, continuité et Bézier auto spatiaux, déplacement libre, couleur `keyLabel`, sélection), la retirer (`removeKey`, de la plus haute à la plus basse), puis `addKey(t)` + `setValueAtKey` et reposer dans cet ordre : type d'interpolation, ease (seulement si un côté est en Bézier et pas en auto), continuité puis Bézier auto, tangentes (ou Bézier auto spatial), couleur. Le déplacement libre se repose **après** avoir recréé toutes les keyframes (refusé sur la première et la dernière, et la keyframe qu'on vient d'ajouter est provisoirement la dernière). Une keyframe arrivée sur une autre la remplace. Retirer une keyframe en déplacement libre fait recalculer le temps de ses voisines en déplacement libre. Marqueurs, valeurs personnalisées : ne pas y toucher. En cas d'échec en cours de route, reposer les keyframes à leur place d'origine. À vérifier dans AE : ease et tangentes identiques après coup, keyframes de Source Text.
- **Décaler un calque dans le temps** : `layer.startTime += dt` emporte ses keyframes et ses points d'entrée / sortie. Pour aligner des départs, comparer `inPoint` (un calque rogné commence après son `startTime`).
- **`comp.layers.addNull(durée)` / `addShape()`** : le calque arrive tout en haut (index 1) ; les autres descendent d'un cran (penser à `+ 1` avant `moveBefore`). Son début n'est pas garanti à 0 (préférence « Créer les calques au début de la composition ») : poser `startTime`, `inPoint`, `outPoint`. Contenus d'une forme : `property('ADBE Root Vectors Group').addProperty('ADBE Vector Group')`, puis `property('ADBE Vectors Group').addProperty('ADBE Vector Shape - Rect' | 'ADBE Vector Graphic - Fill')`. Ajouter une propriété **invalide les références** aux propriétés voisines déjà lues : les relire depuis le calque.
- **Calque de forme recréé d'après un PSD** (2026-11-09, `psdimport.replaceWithShape`) : **un seul `ADBE Vector Group`** pour tous les sous-tracés (une union remplie une fois ; un groupe par sous-tracé recouvrirait ses voisins et cumulerait les opacités), puis dedans, dans l'ordre d'ajout, les tracés (`ADBE Vector Shape - Rect` / `- Ellipse` / `- Group`), `ADBE Vector Graphic - Stroke`, `ADBE Vector Graphic - Fill` (un contour doit être au-dessus du remplissage). Plusieurs sous-tracés avec contour, ou dont un est tourné : refusé (le calque reste en PSD). Rect et ellipse : `Size` + `Position` = centre ; pour les tourner autour de leur centre, ancre et position du groupe (`ADBE Vector Transform Group` › `ADBE Vector Anchor` / `ADBE Vector Position`) = centre, angle sur `ADBE Vector Rotation`. Tracé libre : `new Shape()` (`vertices`, `inTangents`, `outTangents` relatives au sommet, `closed`) écrit dans `ADBE Vector Shape`. Opacité du remplissage : `ADBE Vector Fill Opacity` (`ADBE Vector Stroke Opacity` pour le contour). Le contour d'une forme est **toujours centré** sur le tracé (pas d'intérieur / extérieur) ; sa limite des angles vaut 4 par défaut dans After contre 100 dans Photoshop (`ADBE Vector Stroke Miter Limit`) : celle du PSD (`strokeStyleMiterLimit`) est écrite. Après un `addProperty`, régler aussitôt l'élément rendu, avant tout autre ajout. **Constaté (After 26.2, 2026-11-10)** : les couleurs d'un dégradé de calque de forme sont inaccessibles (voir « Dégradés » plus bas). **À vérifier dans After** (le faux AE des tests ne le prouve pas) : `BlendingMode.SUBTRACT` / `DIVIDE` peuvent manquer selon la version (mode alors non reproductible) ; `layer.remove()` sur un calque verrouillé (lever le verrou avant, le reporter sur le nouveau calque) ; `new Shape()` accepté par `ADBE Vector Shape`.
- **Point ciblé d'une caméra ou d'une lumière** : c'est `ADBE Anchor Point` dans sa transformation (à recentrer avec la position quand la comp change de taille). À vérifier : caméra à un nœud.
- **Changer la taille d'une comp** (`comp.width`, `comp.height`) ne bouge aucun calque : le contenu se décale vers le haut à gauche. Recentrer soi-même les calques sans parent (moitié de l'agrandissement), keyframes comprises. **Constaté (2026-11-10)** : After remet en revanche à l'échelle l'**ancre** des calques qui affichent cette comp dans d'autres comps (500 → 200 quand la largeur passe de 1000 à 400) ; pour la garder, la relever avant et la reposer après (`cropPrecomp`, `psdimport.jsx`).
- **Fenêtre de choix de dossier** : `Folder.selectDialog` / `folder.selectDlg` donnent sous Windows l'ancien arbre de dossiers. Côté panneau, `window.cep.fs.showOpenDialogEx(false, true, titre, dossierDeDépart, [])` (CEP) rend `{ err, data: [chemin] }` ; à vérifier dans After : Explorateur moderne sous Windows.
- **Import de SVG (After Effects 2026)** (2026-11-06, AE 26.2.1 macOS, Metal) : `app.project.importFile` accepte un `.svg` (métrage vectoriel ; `collapseTransformation` possible). Rendre un SVG qui contient du **texte** a fait planter After Effects : `abort` dans le fil « #BEE WorkQueue General Render Thread », pile `AdobeSVGRE` → `AdobeAGM` → `AdobeCoolType`, 0,2 s après l'import par script et `comp.openInViewer()` (5 SVG à texte DM Sans, police variable, et Permanent Marker, installées avant le lancement d'AE). N'importer que des SVG sans texte (texte retiré ou vectorisé) et recréer les textes en calques texte ; la consigne est dans les instructions MCP données à Claude. À vérifier : un SVG à texte importé à la main (fenêtre d'options d'import SVG) plante-t-il aussi ? Police non variable ?
- **Après un plantage d'After Effects** : pas de rapport dans `~/Library/Logs/DiagnosticReports` ; After Effects écrit un vidage Sentry dans `~/Library/Caches/Adobe/After Effects/<version>/SentryIO-db/completed/<id>.dmp`, et à côté (`attachments/<id>/`) `__sentry-breadcrumb1` (heure exacte, signal, nom du fil) et `__sentry-event` (version, drapeaux). Le module fautif et les modules de la pile se lisent dans le minidump (flux exception 6, modules 4, fils 3). Les extensions CEP, elles, écrivent « Heartbeat call failed » une vingtaine de secondes plus tard.
- **`comp.saveFrameToPng(t, File)`** (non documentée, AE 2020+) : rend la frame en PNG. Le fichier peut n'être complet qu'après le retour du script : le panneau relit sa taille jusqu'à ce qu'elle soit stable. À vérifier : résolution (pleine ou celle de la vue), délai réel.
- **Préférence « Autoriser les scripts à écrire des fichiers et à accéder au réseau »** : écrire un fichier, `saveFrameToPng` et `system.callSystem` en dépendent. Lue par `app.preferences.getPrefAsLong('Main Pref Section', 'Pref_SCRIPTING_FILE_NETWORK_SECURITY')` (on essaie aussi `Main Pref Section v2`) : 1 = permis. Si elle ne se lit pas, tenter quand même et expliquer en cas d'échec.
- **`system.callSystem(cmd)`** : synchrone (After Effects attend), fenêtre console possible sous Windows, accents du chemin selon la page de code ANSI. Préférer Node dans le panneau (CEP) ; garder `callSystem` en repli.
- **`app.findMenuCommandId(nom)`** attend le nom **dans la langue d'After Effects** (et parfois le seul libellé du sous-menu) : essayer plusieurs noms anglais et français. Ne jamais lancer un identifiant numérique non vérifié : `executeCommand` exécuterait n'importe quelle commande. `app.executeCommand` agit sur la sélection de la comp active : isoler la sélection avant, vérifier le résultat après (ex. un calque texte est-il apparu ?). **Constaté (After 26.2, 2026-11-10)** : le nom d'une commande n'est pas fiable pour les styles de calque (`findMenuCommandId('Ombre portée')` renvoie 2452, l'**effet** Ombre portée ; plusieurs noms renvoient 0) ; les identifiants numériques des styles (9000 ombre portée, 9001 ombre interne, 9002 lueur externe, 9003 lueur interne, 9004 biseautage, 9005 satin, 9006 incrustation couleur, 9007 incrustation en dégradé, 9008 contour) sont indépendants de la langue mais ne servent plus à rien (voir « Styles de calque »). Copier = 19 et Coller = 20 sont des identifiants vérifiés.
- **`$.colorPicker(0xRRGGBB)`** ouvre le sélecteur de couleur du système (modal) et renvoie la couleur choisie en entier, ou -1 si annulé.
- **`app.project.selection`** : éléments sélectionnés du panneau Projet ; `item.selected = true / false` les change (sans faire défiler le panneau ni ouvrir les dossiers : c'est la commande « Reveal Layer Source in Project » qui le fait).
- **`comp.duplicate()`** (2026-10-07) : renvoie la copie (« Pub 2 ») ; calques recopiés, précompos imbriquées partagées (pas dupliquées). À vérifier : dossier de la copie dans le projet.
- **Rogner une comp à sa zone de travail par script** : reculer `layer.startTime` de chaque calque (déverrouiller le temps de le faire) et les marqueurs de comp (`comp.markerProperty` : relire, retirer, reposer), avancer `comp.displayStartTime` d'autant pour garder le timecode, puis `workAreaStart = 0`, `workAreaDuration`, et seulement après `comp.duration`. Pour changer la zone de travail, réduire d'abord `workAreaDuration` (sinon un nouveau début + l'ancienne durée peut dépasser la comp).
- **Convertir une expression en keyframes** : échantillonner `valueAtTime(t, false)` à chaque image **avant** de retirer les keyframes existantes, puis `expressionEnabled = false` (le texte reste) et `setValuesAtTimes(temps[], valeurs[])` (bien plus rapide qu'une boucle de `setValueAtTime`). `expressionError` non vide : l'expression ne marche pas, ne rien toucher. Alléger les valeurs constantes seulement hors position (une tangente automatique ferait boucler le tracé entre deux keyframes égales) et hors texte.
- **`File.copy(cible)`** copie un fichier (remplacer d'abord une cible existante avec `remove()` par prudence) ; `app.project.file` est null tant que le projet n'a jamais été enregistré. `File.name` est encodé (`%20`) : afficher `displayName`.
- **Lister un dossier en profondeur** (2026-11-10) : `Folder.getFiles()` mêle `File` et `Folder` (les distinguer par `instanceof`) et renvoie aussi les cachés (nom commençant par « . », dont les `._*` de macOS : à écarter à la main). `Folder.name` est encodé comme `File.name` : `displayName` ou `File.decode(name)` pour un nom de dossier recréé dans le Projet. Borner la profondeur (liens, boucles).
- **Dossiers du panneau Projet** (2026-11-10) : `app.project.items.addFolder(nom)` crée toujours à la racine ; pour l'imbriquer, `dossier.parentFolder = parent`. Un élément de la racine a `parentFolder` = `app.project.rootFolder` (pas null). Comparer les dossiers par `id`, jamais par `===`. Retirer un dossier retire son contenu.
- **Montrer un fichier** : `explorer.exe /select, "chemin"` (rend le code de sortie 1 même quand tout va bien) ; macOS : `open -R chemin` ; un dossier : `explorer.exe chemin` / `open chemin`.
- **`comp.selectedLayers`** : ordre des clics, ou de haut en bas ? (Les notes plus haut disent « ordre de sélection », une relecture dit « ordre de la pile ».) À vérifier dans AE : la Boîte à outils séquence dans l'ordre que renvoie AE.
- **Choisir un dossier** (2026-11-09) : la méthode statique `Folder.selectDialog(invite)` ne prend qu'une invite ; un second argument est ignoré et le dialogue s'ouvre au dernier dossier utilisé. Pour partir d'un dossier précis : `dossier.selectDlg(invite)` (méthode d'instance, le dossier doit exister). Les deux rendent un `Folder` ou `null` si l'utilisateur annule. Le faux AE des tests reproduit cette différence (`selectDlg` note son dossier de départ, `selectDialog` n'en a pas).
- **Styles de calque par script** (constaté dans After 26.2, 2026-11-10, Import PSD) : aucune API ne les crée, et recréer les réglages à la main était fragile (noms de menu faux, groupes mal nommés). **After importe un PSD (`COMP_CROPPED_LAYERS`) avec ses styles de calque MODIFIABLES** (sur `7.psd`, « Rectangle » a une lueur externe active, « etoile » une lueur externe et une incrustation couleur ; le métrage ne contient pas les pixels des styles). Import PSD les **recopie tels quels** du calque PSD sur la forme (`copyLayerStyles`) : dans la compo ouverte dans le visualiseur (`comp.openInViewer()`), tous les calques désélectionnés, `src.property('ADBE Layer Styles').selected = true`, `app.executeCommand(19)` (Copier), `selected = false`, calques désélectionnés, `dst.selected = true`, `app.executeCommand(20)` (Coller) : le groupe de `dst` devient visible avec les mêmes styles et valeurs, d'un calque PSD vers un calque de forme. Le presse-papiers de l'utilisateur est écrasé (accepté). **Noms réels des groupes** sous `ADBE Layer Styles` : `ADBE Blend Options Group`, `dropShadow/enabled`, `innerShadow/enabled`, `outerGlow/enabled`, `innerGlow/enabled`, `bevelEmboss/enabled`, `chromeFX/enabled` (satin), `solidFill/enabled`, `gradientFill/enabled`, `patternFill/enabled`, `frameFX/enabled` (contour) ; propriétés `dropShadow/distance`, `dropShadow/blur`, `outerGlow/blur`, `bevelEmboss/blur`, `frameFX/size`… Un style présent a `group.enabled === true`, absent `false`. Le groupe `ADBE Layer Styles` d'un calque **sans style est « masqué »** : lui donner `selected = …` lève une erreur (« la propriété ou une propriété parent est masquée ») ; c'est le test fiable de « le calque a des styles », et de « le collage a marché ». **Options de fusion copiées** : `ADBE Blend Options Group` › `ADBE Adv Blend Group` › `ADBE Layer Fill Opacity2` (opacité du fond) et l'angle global (`ADBE Global Angle2`, `ADBE Global Altitude2`) font partie de la copie : une forme recréée avec des styles garde donc remplissage ET contour à 100 % (sinon l'opacité du fond s'appliquerait deux fois). `app.executeCommand` agit sur la composition active : `copyLayerStyles` vérifie que la compo du calque est `app.project.activeItem` (comparaison des `id`), sinon panne visible ; un collage sans effet (groupe de la forme toujours masqué) est une panne visible aussi, la forme à demi faite est retirée et l'original reste. `styleOverflow` (précompos recadrées) lit les groupes `<sorte>/enabled` et leurs propriétés. `deselectLayers` est dans `SIMING.ae`.
- **Import PSD en lot : viewer et dossier du Projet** (2026-11-09, `psdimport.importBatch`) : `app.executeCommand` (conversion en texte, Copier / Coller des styles de calque) agit sur la composition du **viewer**, pas sur celle dont on tient l'objet : l'import appelle `comp.openInViewer()` avant, **vérifie** que `app.project.activeItem` est bien cette compo (`id`) — sinon (visualiseur verrouillé, focus ailleurs…) l'étape (formes, textes) est sautée pour cette compo avec un avertissement (« Compo non active dans le visualiseur »), aucune commande lancée, et le PSD reste importé — et rouvre à la fin la compo qui était active. Seul un échec de l'import ou du rangement rend un PSD « illisible » et retire ce qu'il avait créé. Effet de bord : **une compo reste ouverte dans un onglet de la Timeline** par compo qui a des formes à remplacer ou des textes à convertir (un PSD à groupes en laisse plusieurs). À vérifier dans After : `importFile` range-t-il les éléments créés à la racine du Projet, ou dans le dossier sélectionné dans le panneau Projet (comme Fichier › Importer) ? Le rangement vers `02_ASSET` prend **tout élément neuf dont le parent n'est pas neuf** (la racine comme un dossier sélectionné) : la réponse ne change pas le résultat, elle sert à confirmer que le cas « dossier sélectionné » est bien couvert. Le métrage d'un calque de PSD s'appelle `<calque>/<fichier>.psd` : le nom du calque se lit en coupant au **dernier** « / ».
- **Import PSD : ce qui reste à constater dans After, dans l'ordre du scénario `TESTS-MANUELS.md` § Importer les PSD** (2026-11-09, mis à jour 2026-11-10) : (1) ~~styles modifiables ou fusionnés~~ **modifiables** (voir « Styles de calque ») ; l'original est retiré avec `layer.remove()`, ses styles avec lui, ceux de la forme sont des copies. (2) Un seul groupe d'annulation (`SIMING.ae.undo`) pour l'import, les formes, les textes, les libellés et les copier-coller de styles ; si After en fait deux (`executeCommand` ouvrant sa propre entrée d'annulation ?), l'écrire ici et dans le statut. (3) Les formes recréées recouvrent l'original au pixel près (décalage document → compo calculé depuis le calque PSD, coin du plan de travail compris). **Constaté (AE, 2026-11-09)** : un calque de pixels arrive rogné à sa boîte, mais un **calque de forme** (remplissage + tracé vectoriel) arrive en métrage **à la taille du document**, ancre au centre, son tracé devenu masque, même avec `COMP_CROPPED_LAYERS`. `replaceWithShape` accepte donc les deux tailles (`footageOrigin` : boîte → coin = box, document → coin = 0, 0 ; 1 px de tolérance) et, pour une boîte qui **déborde du document** (fond plus grand que la planche), aussi la part de la boîte dans le document (coin = celui de cette part) : on ne sait pas encore si After rogne alors le métrage au document ou le garde entier, le code accepte les deux (**à constater dans After sur un fond qui déborde**) ; sinon (styles fusionnés dans les pixels, JSON d'un autre calque), ne pose rien et note une panne (« forme en erreur »). (4) Dégradés : voir « Dégradés ».
- **Dégradés de calque de forme** (constaté dans After 26.2, 2026-11-10, Import PSD) : les couleurs d'un dégradé (`ADBE Vector Grad Colors`, et `gradientFill/gradient` d'un style) ont `propertyValueType === NO_VALUE` : ni lecture, ni `setValue`, ni expression. **Ne pas tenter de contournement par fichier** (PDF / AI converti par la commande 3973 « Créer des formes à partir du calque vectoriel ») : cela a produit un dégradé invalide qui a bloqué After en boucle d'erreurs. **L'effet « Dégradé » (`ADBE Ramp`) convient** : posé sur un calque de forme, il respecte la forme (alpha 0 dehors) ; `ADBE Ramp-0001` point de départ, `-0002` couleur de départ, `-0003` point d'arrivée, `-0004` couleur d'arrivée, `-0005` type (1 linéaire, 2 radial), `-0006` dispersion, `-0007` part de l'original ; points en coordonnées du calque (le calque de forme recréé a l'ancre [0, 0] et des tracés en coordonnées du document : points tels quels) ; interpolation linéaire, identique au mélange d'un dégradé. L'effet colore tout le calque, contour compris : un dégradé avec un contour reste en PSD. **Géométrie d'un dégradé linéaire de calque de remplissage Photoshop** (mesurée sur « Ellipse 1 » de la planche test : boîte 184,193 → 537,546, angle 129°, bleu → gris) : aligné sur le calque, centré sur le centre de la boîte, direction (cos θ, −sin θ) (y vers le bas), longueur L = |l·cos θ| + |h·sin θ| (l, h : taille de la boîte), départ = centre − dir·L/2 (premier arrêt), arrivée = centre + dir·L/2. Le « lissage » de Photoshop (`Intr` = 4096, 100 %) adoucit les extrémités : écart d'une dizaine de niveaux sur 255, accepté. Seuls les dégradés linéaires à deux couleurs RVB, opaques, alignés, sans échelle ni décalage ni milieu d'arrêt déplacé, interpolés en « Classique » sont recréés ; tout le reste reste un calque PSD.

## CEP (à compléter pendant l'implémentation)

- Le panneau (Chromium) et le moteur ExtendScript sont séparés : ils ne s'échangent que des chaînes via `CSInterface.evalScript(script, callback)`. Le callback reçoit `EvalScript error.` si le script échoue sans être attrapé.
- ExtendScript n'a pas `JSON` : le cœur hôte fournit son propre `stringify` / `parse` (sans `eval`).
- En développement, les extensions non signées ne se chargent qu'avec `PlayerDebugMode = 1` pour la version CSXS concernée (registre Windows `HKCU\Software\Adobe\CSXS.<n>`, préférences macOS `com.adobe.CSXS.<n>`).
- Sous macOS, après `defaults write com.adobe.CSXS.<n> PlayerDebugMode 1`, il peut falloir `killall cfprefsd` (ou une reconnexion) pour que After Effects voie le réglage.
- `CSInterface.evalScript` est asynchrone : un seul appel à la fois par vue, commandes désactivées pendant l'appel (une seule action par double clic).
- Les arguments passent encodés (`encodeURIComponent` du JSON) et le retour aussi : aucun texte de calque n'est interprété comme du code.
- Un panneau CEP ne lit pas de paramètres fiables dans `MainPath` : le panneau isolé déduit son outil de `CSInterface.getExtensionID()`.
- Tous les panneaux d'une extension partagent le moteur ExtendScript : chaque panneau recharge `host/siming.jsx` (mémoire de session d'Unparent remise à zéro, les balises suffisent).
- **Raccourcis clavier** (2026-10-06) : écouter `keydown` sur `document` et comparer `e.code` (touche physique : `Digit1`, `KeyQ`, `Numpad5`), jamais `e.key`, qui dépend de la disposition. En AZERTY la rangée de chiffres se tape avec Maj (`e.key` = `&`, `e.code` = `Digit1`) : ignorer Maj sur `Digit…`. Pour l'affichage, prendre la lettre réellement frappée (`e.key`) et une table pour le reste (Entrée, Pavé 5, ↑). Un panneau ne reçoit les touches que lorsqu'il a le focus (clic dedans) ; Entrée et Espace sur un bouton focalisé déclenchent le clic natif, ne pas les intercepter.
- **Combinaisons de touches dans un panneau CEP** (2026-10-06) : After Effects garde pour lui les frappes avec Ctrl, Alt ou Cmd (ses propres raccourcis) tant que le panneau ne les a pas réclamées par `CSInterface.registerKeyEventsInterest(JSON)` : un tableau `{ keyCode, ctrlKey?, altKey?, shiftKey?, metaKey? }`, keyCode = touche virtuelle Windows (VK_…, 0x35 pour 5) ou code de touche macOS (kVK_…, 0x17 pour 5). Chaque appel remplace le précédent (à vérifier). Pour capturer un raccourci neuf, réclamer toutes les touches le temps de la capture. Voir `SIMING.keys.interest` et `SIMING.claimKeys`.
- **Node dans le panneau** (2026-10-07) : paramètre CEF `--enable-nodejs` dans le manifeste. Sans `--mixed-context`, Node vit dans un contexte séparé : `cep_node.require('child_process')` (parfois aussi `require` global). `execFile(programme, arguments, { windowsHide: true })` lance un programme sans shell ni fenêtre : c'est ainsi que la Boîte à outils met une image dans le presse-papier (PowerShell en STA sous Windows, `osascript -l JavaScript` sous macOS). À vérifier dans AE : `cep_node` présent (CEP 11 et 12).
- **CSS du panneau** : CEP 11 embarque Chromium 88. Pas de requêtes de conteneur (`@container`, Chromium 105) ni de `scrollbar-color` (Chromium 121) : mises en page étroites par `flex-wrap`, grilles `auto-fit` et `@media (max-width)` (le panneau est la fenêtre) ; barre de défilement par `::-webkit-scrollbar`. Une barre de valeur `flex: 1` dans une colonne flex se tasse : `flex: none`.
- **`localStorage` entre panneaux** : le hub et un panneau isolé sont deux extensions du même bundle ; à vérifier dans AE si elles partagent le même `localStorage` (sinon l'ordre et les raccourcis choisis dans le hub ne s'appliquent pas au panneau isolé, qui garde les défauts).
- Ouvrir un panneau isolé ré-exécute `siming.jsx` dans ce moteur partagé et vide donc la mémoire de session du hub ouvert à côté. Conséquence : **la balise fait foi**. La mémoire n'est qu'un reflet des balises : un calque sans balise n'est jamais considéré comme détaché, même si la mémoire disait le contraire (cas d'un Ctrl+Z, qui retire la balise sans prévenir le panneau).

- **Extension invisible** (2026-11-06, service Claude Code `com.siming.mcp`) : `<Type>Custom</Type>`, `<AutoVisible>false</AutoVisible>`, pas de `<Menu>` (absente de Fenêtre › Extensions), `<StartOn>` avec `applicationActivate`, `com.adobe.csxs.events.ApplicationActivate` et `com.adobe.csxs.events.ApplicationInitialized`. After Effects ne figure pas dans le tableau de compatibilité des extensions invisibles du CEP Cookbook et des développeurs disent qu'il ne les démarre pas toujours : le hub demande donc `requestOpenExtension('com.siming.mcp')` quand le service ne répond pas. Vérifié sur macOS, AE 26.2.1 (2026-11-06) : l'extension invisible démarre seule au lancement d'After Effects (son journal `CEPHtmlEngine12-AEFT-26.2.1-com.siming.mcp.log` apparaît, sans panneau ouvert). À vérifier : Windows ; `requestOpenExtension` sur une extension invisible.
- **Événements entre extensions** : `new CSEvent(type, 'APPLICATION')`, `ev.data = JSON.stringify(…)`, `cs.dispatchEvent(ev)` ; chaque extension du même hôte qui a fait `addEventListener(type, fn)` le reçoit. Selon la version de CEP, `event.data` arrive en texte ou déjà lu en objet : `SIMING.mcp.eventData` accepte les deux.
- **Serveur HTTP dans un panneau** : `cep_node.require('http').createServer(...)` marche en contexte séparé (les rappels du navigateur sont appelés depuis Node). Écouter `127.0.0.1` seulement. `server.close()` attend les connexions gardées ouvertes par le client (keep-alive) : les noter à `connection` et les détruire pour libérer le port aussitôt. Port pris : erreur `EADDRINUSE` au `listen`.
- **Données de l'utilisateur** : `cs.getSystemPath(SystemPath.USER_DATA)` = `~/Library/Application Support` (macOS), `%APPDATA%` (Windows) ; le hub et le service y partagent `SIMING/claude.json` (le `localStorage` n'est peut-être pas commun aux extensions du bundle).

## Installation (macOS)

- **Savoir si After Effects tourne** (2026-10-12) : `pgrep -x "After Effects"` (nom exact du processus de l'application, `Contents/MacOS/After Effects`). Jamais `pgrep -f "Adobe After Effects"` : l'option `-f` cherche dans la ligne de commande complète, donc dans le chemin de tous les processus d'appoint rangés dans le dossier d'AE (CEPHtmlEngine des panneaux, rapporteur de plantage…), qui survivent parfois à sa fermeture ou à un plantage. L'installeur 1.3.0 bouclait ainsi sur « ferme-le ».
- Sous macOS, fermer la fenêtre d'After Effects ne le quitte pas : il faut Cmd + Q. Une attente « quitte After Effects » donne aussi une sortie (`i` = installer quand même) et s'arrête si `read` n'a plus de clavier (`|| finish 1`), sinon elle tourne à vide.
- Un lien de développement (`tools/dev-install.command --link`) dans `~/Library/Application Support/Adobe/CEP/extensions/com.siming` occupe le dossier où l'installeur extrait SIMING : l'installeur retire le lien (`rm` sur le lien, jamais `rm -r`, qui suivrait vers le dépôt). Sous Windows, jonction retirée par `cmd /c rmdir` (sans `/s`).
- **UPIA ne marche plus seul** (2026-11-09, Creative Cloud récent) : `UnifiedPluginInstallerAgent /install` passe par l'application Creative Cloud (« vulcan ») ; non connecté, il échoue avec `status = -631` (« user not signed in » dans `%APPDATA%\Adobe\UPI\Log\Upia.log`) **et sort avec le code 0** : l'ancien installeur annonçait « installé ». Les installeurs n'utilisent plus UPIA : ils extraient le `.zxp` (un zip) tel quel dans le dossier CEP de l'utilisateur ; la signature (`META-INF/signatures.xml`) suffit, sans PlayerDebugMode ni droits administrateur. Ne rien ajouter dans le dossier installé (fichier hors signature). UPIA ne sert plus qu'à retirer une ancienne copie du dossier système (`--remove SIMING`, au mieux), puis suppression avec élévation.
- **Extension reliée à un disque externe** (2026-11-06) : le lien de développement pointait vers `/Volumes/EXT 11/…` ; le disque, renommé KINGSTON (ou simplement éjecté, démonté par la mise en veille), laissait un lien mort et SIMING disparaissait d'After Effects (dernier journal `CEPHtmlEngine12-AEFT-…-com.siming.hub.log` : « mach port died », « Heartbeat call failed »). Sous Windows, la jonction vers une lettre de lecteur fixe tenait. Correction : `dev-install.command` **copie** l'extension sur le disque interne (sans `._*` ni `.DS_Store`, attributs étendus retirés). macOS remet `com.apple.provenance` sur les fichiers copiés : sans effet sur CEP (ce n'est pas la quarantaine).
- **Journaux CEP** : `~/Library/Logs/CSXS/` (`CEP12-AEFT.log`, un `CEPHtmlEngine12-AEFT-<version>-<extension>.log` par extension chargée). After Effects 2026 (26.x) = CEP 12 (PlugPlug 12.0.1), `PlayerDebugMode` de `com.adobe.CSXS.12`. Un fichier de journal qui n'apparaît pas pour une extension = elle n'a pas été chargée.
- **Fichiers « ._ »** (2026-11-06) : sur un disque non Apple (exFAT, comme le disque KINGSTON), macOS écrit un fichier `._<nom>` à côté de chaque fichier qui porte des attributs étendus. `folder.getFiles('*.jsx')` les voit (`._mcp.jsx` serait évalué comme du code) et ZXPSignCmd les signerait. `SIMING.loadTools`, le test de syntaxe et `add-bom.js` les ignorent ; `release.js` les retire de `extension/` avant de signer.
